# 一、扫码枪怎么接入？

## 1. 推荐买什么扫码枪？

建议你买：

> **支持 USB HID 键盘模式的扫码枪**

无论是有线、2.4G 无线接收器、蓝牙，都可以。重点是：  **扫码枪要能被电脑识别成键盘。**

你买的时候可以问客服：

> 这个扫码枪是否支持 USB HID 键盘模式？  
> 是否可以模拟键盘输入？  
> 是否支持添加回车结束符？

只要支持 **USB HID 键盘模式**，程序就很好做。

---

## 2. 扫码枪工作原理

大部分扫码枪默认是这样工作的：

```text
扫码枪扫码
  ↓
模拟键盘快速输入条码
  ↓
最后自动输入一个回车键
```

比如条码是：

```text
6901234567890
```

扫码枪实际上相当于有人在键盘上极快地输入：

```text
6901234567890 + 回车
```

所以我们的程序只要监听一个输入框里的回车事件即可。

---

## 3. 有线和无线有区别吗？

没有本质区别。

### 有线扫码枪

插上 USB，电脑识别为键盘。

### 2.4G 无线扫码枪

带一个 USB 接收器，电脑通常也识别为键盘。

### 蓝牙扫码枪

如果配对后是 HID 键盘模式，也可以。

### 不推荐的类型

如果扫码枪是：

- 串口模式；
- COM 口模式；
- 虚拟串口模式；
- 工业总线模式；

那就需要额外读取串口，程序会复杂一些。

所以购买前确认：

> 必须支持 USB HID 键盘模式。

---

## 4. 怎么测试扫码枪是否接入成功？

非常简单：

1. 把扫码枪插到电脑；
2. 打开记事本；
3. 扫一个条码；
4. 如果记事本里出现条码，并且光标换行了，说明接入成功。

例如：

```text
6901234567890
```

如果没有换行，只是出现条码，说明扫码枪可能没有配置“回车结束符”。

你需要根据扫码枪说明书设置：

> 添加回车结束符  
> 添加换行结束符  
> USB 键盘模式  
> HID Keyboard Mode

不同品牌叫法不一样。

# 二、程序整体方案

程序界面大概这样：

```text
Excel 文件：[选择文件]
条码列：1
首行是表头：勾选
忽略大小写：不勾选
启用报警声：勾选

[加载清单] [重置进度] [跳过当前] [回退一个] [清空日志]

扫码输入框：
--------------------------------------------------
等待扫第 3/100 个，期望条码：6901234567892

日志：
10:21:05 [OK] 第 1/100 个：6901234567890
10:21:08 [OK] 第 2/100 个：6901234567891
10:21:11 [NG] 第 3/100 个 顺序不一致！期望：6901234567892，实际：6901234567999
```

程序逻辑：

1. 启动程序；
2. 选择 Excel 文件；
3. 点击“加载清单”；
4. 程序读取 Excel 中的条码列表；
5. 扫码枪扫一次条码；
6. 程序立即比对当前顺序；
7. 如果正确：
   - 日志记录；
   - 进入下一个条码；
8. 如果错误：
   - 日志记录；
   - 声音报警；
   - 当前顺序不前进，等待重新扫正确码；
9. 支持跳过当前、回退上一个、重置进度。

# 三、Excel 数据格式建议

建议用 `.xlsx` 文件。

例如文件名为：

```text
standard_barcodes.xlsx
```

## 示例 1：只有一列条码

如果第一行是表头：

| 条码          |
| ------------- |
| 6901234567890 |
| 6901234567891 |
| 6901234567892 |
| 6901234567893 |

程序设置：

```text
条码列：1
首行是表头：勾选
```

---

## 示例 2：有顺序号和条码两列

| 顺序 | 条码          |
| ---: | ------------- |
|    1 | 6901234567890 |
|    2 | 6901234567891 |
|    3 | 6901234567892 |

程序设置：

```text
条码列：2
首行是表头：勾选
```

---

## 重要提醒：条码列最好设置成文本格式

如果你的条码很长，例如：

```text
6901234567890123
```

Excel 有可能自动转成数字，甚至变成：

```text
6.90123E+14
```

这样会导致比对失败。

建议你：

1. 在 Excel 中选中条码列；
2. 设置单元格格式为“文本”；
3. 再粘贴条码；
4. 另存为 `.xlsx` 或 `.csv`。

如果条码来自系统导出，**CSV 文件通常更稳定**。

我下面给你的代码同时支持：

```text
.xlsx
.xlsm
.csv
.txt
```

# 七、运行程序

命令行进入代码所在目录，然后执行：

```bash
python scanner_check.py
```

运行后会弹出窗口。

操作步骤：

1. 点击“浏览...”；
2. 选择 Excel 或 CSV 条码文件；
3. 设置条码列；
   - 如果条码在第一列，填 `1`；
   - 如果条码在第二列，填 `2`；
4. 如果第一行是表头，勾选“首行是表头”；
5. 点击“加载清单”；
6. 鼠标光标保持在“扫码输入框”中；
7. 使用扫码枪扫码；
8. 每扫一次，程序立即比对一次。

# 八、程序行为说明

## 1. 扫码正确

假设当前期望第 3 个条码：

```text
6901234567892
```

扫码枪扫到：

```text
6901234567892
```

程序会：

```text
[OK] 第 3/100 个：6901234567892
```

然后自动进入第 4 个。

---

## 2. 扫码错误

假设当前期望第 3 个条码：

```text
6901234567892
```

扫码枪扫到：

```text
6901234567999
```

程序会：

```text
[NG] 第 3/100 个顺序不一致！期望：6901234567892，实际：6901234567999
```

同时发出报警声。

此时程序默认不会前进。

也就是说：

> 错误后，仍然停在当前顺序，直到扫到正确条码，或者人工点击“跳过当前”。

这样比较符合顺序校验场景。

---

## 3. 跳过当前

如果当前条码确实丢失、损坏、无法扫出，可以点击：

```text
跳过当前
```

程序会跳到下一个条码。

日志会记录：

```text
SKIP
```

---

## 4. 回退一个

如果不小心扫错了，或者误操作跳过了，可以点击：

```text
回退一个
```

程序会回到上一个条码。

---

## 5. 重置进度

点击：

```text
重置进度
```

会从第 1 个重新开始。

# 十、如何打包成 exe？

如果你要部署到电脑，不想安装 Python，可以打包成 `.exe`。

安装 PyInstaller：

```bash
pip install pyinstaller
```

然后在代码目录执行：

```bash
pyinstaller --onefile --windowed --name ScanChecker --collect-all openpyxl scanner_check.py
```

参数解释：

```text
--onefile       打包成单个 exe
--windowed      不显示黑色命令行窗口
--name          生成的程序名
--collect-all   尽量收集 openpyxl 相关资源，避免打包后读取 Excel 失败
```

打包完成后，在这个目录：

```text
dist/
```

里面会有：

```text
ScanChecker.exe
```

你可以把它复制到目标电脑运行。

# 十一、常见问题

## 1. 扫码枪扫了没反应？

检查：

1. 扫码枪是否被电脑识别？
2. 打开记事本扫码，看是否出现条码？
3. 程序里的“扫码输入框”是否有光标？
4. 输入法是否处于中文状态？

建议：

> 切换到英文输入法，或者关闭中文输入法。

有些扫码枪模拟键盘输入时，中文输入法会影响输入。

---

## 2. 扫码后不自动比对？

大概率是扫码枪没有发送回车。

打开记事本扫码：

如果条码后面没有换行，说明没有回车结束符。

请根据扫码枪说明书设置：

```text
添加回车结束符
```

或者：

```text
Add CR suffix
Add Enter suffix
USB Keyboard Mode
```

---

## 3. Excel 条码变成科学计数法怎么办？

例如显示：

```text
6.90123E+14
```

这说明 Excel 把条码识别成数字了。

解决方法：

1. 选中条码列；
2. 设置单元格格式为“文本”；
3. 重新粘贴条码；
4. 保存为 `.xlsx` 或 `.csv`。

更推荐用 `.csv`。

---

## 4. 正确条码被判断错误？

检查：

1. 条码前后是否有空格；
2. 条码是否被 Excel 转成数字；
3. 条码是否包含隐藏字符；
4. 大小写是否一致；
5. 条码列是否选错；
6. 首行表头是否勾选正确。

如果条码包含字母，可以勾选：

```text
忽略大小写
```

---

## 5. 可以不需要界面，后台监听扫码吗？

可以，但不建议首选。

因为扫码枪是键盘输入，如果做全局键盘监听，需要用：

```bash
pip install keyboard
```

但这种方式有几个问题：

1. 可能需要管理员权限；
2. 可能受输入法影响；
3. 扫码内容可能同时输入到当前活动窗口；
4. 稳定性不如 GUI 输入框方案。

所以当前方案使用一个专门的“扫码输入框”，是最稳定、最简单、最适合现场使用的方式。
